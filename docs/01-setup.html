1准备实验环境（EC2 + Coding Agent） A/B 通用

在实验账号里开一台只能通过 SSM 登录的 EC2，所有命令都在这台 EC2 上执行；你的笔记本只用来看手册和 AWS 控制台。

本章出现的 zhang3 是“个人后缀”的示例：2–12 位小写字母或数字、字母开头，同一账号里每人不同（建议用姓名拼音缩写 + 数字）。复制命令时把 zhang3 换成你自己的后缀。
1.1

登录 AWS 控制台并确认区域

3 分钟

确认你在讲师指定的区域（us-west-2 或 us-east-1），后面所有资源都建在这里。

  1. 用讲师发放的账号登录 AWS 控制台。
  2. 点右上角的区域名称，选择讲师指定的区域：美国西部（俄勒冈）us-west-2 或 美国东部（弗吉尼亚北部）us-east-1。
预期结果：控制台右上角显示你选择的区域名。
后面所有控制台操作都要在同一个区域里进行；看不到自己的资源时，先检查右上角的区域。
1.2

一键创建实验 EC2（CloudShell + CloudFormation）

5 分钟

用仓库里的模板创建一台 Amazon Linux 2023 EC2：无入站端口、带 SSM 和实验所需权限。

  1. 点控制台顶部工具栏的 CloudShell 图标 >_，等命令行出现（首次约 30 秒）。
  2. 复制下面整段到 CloudShell 执行（先把最后一行的 zhang3 换成你的后缀）：
mkdir -p ~/s12lab && cd ~/s12lab
curl -fsSLO 
curl -fsSLO 
bash launch-from-cloudshell.sh zhang3

用到的文件：ec2/s12lab-ec2.yaml（CloudFormation 模板）· ec2/launch-from-cloudshell.sh（启动脚本）· 说明 ec2/README.md

预期输出（约 3–5 分钟）：

==> 选择网络（机型 t3.large）...

==> 实例 ID:   i-0123456789abcdef0
==> 登录链接:  https://us-west-2.console.aws.amazon.com/systems-manager/session-manager/i-0123...?region=us-west-2
==> 等待 EC2 在 Session Manager 中上线（最多约 5 分钟）...

  后缀:      zhang3
  区域:      us-west-2
  实例 ID:   i-0123456789abcdef0

1.3

（备选）在控制台手动创建 EC2

10 分钟

CloudShell 不可用时，按截图在控制台点选创建同样的 EC2。

只有 1.2 失败时才做这一步。完整的点击步骤见 ec2/README.md「方式二：控制台手动创建」，要点：

  1. IAM 控制台 → 角色 → 创建角色 → 可信实体 AWS 服务 / EC2 → 勾选 AmazonSSMManagedInstanceCore 和 PowerUserAccess → 角色名 s12lab-ec2-zhang3 → 创建；再给它“创建内联策略”，JSON 粘贴 ec2/manual-iam-inline-policy.json 的内容，策略名 s12lab-iam。
  2. EC2 控制台 → 启动实例：名称 s12lab-zhang3 · AMI Amazon Linux 2023（x86） · 机型 t3.large · 密钥对 在没有密钥对的情况下继续。
  3. 网络设置：默认 VPC、自动分配公有 IP 启用；创建安全组并取消勾选“允许 SSH 流量”（入站规则必须为空）。
  4. 存储 30 GiB gp3；高级详细信息：IAM 实例配置文件选 s12lab-ec2-zhang3，元数据版本 仅 V2，跃点限制 2 → 启动实例。
预期结果：2–3 分钟后实例状态为“正在运行”，选中实例 →「连接」→「Session Manager」选项卡上的「连接」按钮可以点击。
1.4

通过 Session Manager 登录 EC2

2 分钟

在浏览器里打开 EC2 的命令行窗口，不需要密钥、不开端口。

  1. 打开 1.2 打印的登录链接（或：EC2 控制台 → 选中 s12lab-zhang3 →「连接」→「Session Manager」→「连接」）。
  2. 浏览器新标签页里出现黑色命令行后，先切换到 ec2-user：
sudo su - ec2-user
预期输出： 
[ec2-user@ip-10-0-1-23 ~]$
以后每次重新登录都要先执行 sudo su - ec2-user，再 cd ~/scenario12-lab && source .venv/bin/activate。
