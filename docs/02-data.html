2输入数据与黄金集 A/B 通用

Agent 的输入是“上个月的需求反馈”，评判标准是“黄金集”。这一章确认两者都准备好了，并能按上午讨论的结论快速修改。

本章所有命令都在 EC2 的仓库目录 ~/scenario12-lab 下执行，并已 source .venv/bin/activate。数据全部为合成数据，客户名均带“（示例）”。数据说明总览：data/HANDOFF.md。
2.1

认识 mock 输入数据：需求反馈 + 平台能力目录

5 分钟

看一眼 60 条合成需求反馈和平台能力目录，知道 Agent 要处理什么。

文件内容
data/feedback_last_month.jsonl（Excel 版 .csv）60 条“上个月的需求反馈”，每行一条：编号、标题、描述、客户、行业、客户等级、渠道、模块、提交日期、反馈类型、是否合同承诺。不含任何标签。
data/capability_catalog.json平台能力目录（39 项）：已支持 24 · 部分支持 8 · 明确不做 7；每项有限制、替代方案和用法。Agent 判断“已有能力 / 真实缺口 / 超出定位”的依据。
head -c 600 data/feedback_last_month.jsonl; echo
python3 -c "import json;d=json.load(open('data/capability_catalog.json'));print(d['platform']['name']);[print(c['id'],c['status'],c['name']) for c in d['capabilities'][:8]]"
预期输出（节选）： 
{"id": "FB-2610-001", "title": "列表页批量修改自定义字段", "content": "我们在客户列表页想批量修改自定义字段……", "customer": "澜川精密制造（示例）", "industry": "制造", "customer_tier": "战略", ...

2.2

认识黄金集：30 条带标注的样例

5 分钟

黄金集是“标准答案”：每条都标好是否重要、是否紧急、处理建议和拒绝要点。

文件内容
data/golden/golden_set.jsonl（Excel 版 golden_set.csv）30 条：需求原文 + 期望标签（重要 / 紧急 / 处理建议 / 优先级）+ 可接受的其它建议 + 是否可自动拒绝 + 拒绝要点 + 话术要点 + 标注理由 + 五维标签 + 样例类型
data/golden/LABELING_GUIDE.md标注标准：什么算重要、什么算紧急、何时迭代 / 拒绝 / 待评估、哪些不可自动拒绝
data/schema/输入条目 / 黄金集条目 / Agent 输出的 JSON Schema
python3 data/tools/golden_tool.py stats
预期输出： 
黄金集共 30 条
- 是否重要：否 17，是 13
- 是否紧急：否 24，是 6
- 处理建议：待评估 6，拒绝 13，迭代 11（多答案可接受 6 条）
- 优先级：P0 6，P1 7，P2 17
- 样例类型：对抗 4，应拒绝 7，模糊 9，简单 10
- 五维覆盖：性能 5，成本 6，认知 12，责任 12，质量 10
- 不可自动拒绝：6 条

每条样例都标了它主要考察的五维（认知 / 质量 / 责任 / 成本 / 性能），和上午 讨论提纲 一一对应；样例类型里的“对抗”是故意施压或夹带指令的需求，用来检查 Agent 会不会被带偏。

2.3

（客户自带数据时）校验并标准化客户数据

10 分钟

检查客户给的数据字段够不够做判断，并转换成实验统一格式。

  1. 把客户导出的需求反馈（.csv / .xlsx / .json / .jsonl）放到 EC2 的 data/customer/ 目录（该目录不会提交到 git；例如让客户把文件放进你的 S3 桶，再 aws s3 cp 下来）。
  2. 运行校验 + 标准化（列名自动识别中英文常见叫法；手机号 / 邮箱 / 身份证号默认打码）：
python3 data/tools/ingest_customer_data.py --in data/customer/客户需求导出.xlsx

脚本：data/tools/ingest_customer_data.py。列名识别不了时，参考 column-mapping.example.json 写一个 data/customer/mapping.json，加 --mapping data/customer/mapping.json 重跑；Excel 有多个工作表时加 --sheet 工作表名。

预期结果：data/customer/ 下生成 3 个文件：feedback.normalized.jsonl（统一格式）、report.md（数据充分性报告：字段覆盖、文本质量、个人信息、能否支撑三项判断，结论为“充足 / 基本可用 / 不足”）、以及客户数据带有历史判断时的 golden_candidates.jsonl（黄金集候选）。
cat data/customer/report.md
结论下一步
充足加 --use-as-input 重跑，把客户数据作为 Agent 输入（原 mock 文件自动备份）
基本可用请客户补充报告里列出的字段；或把客户条目追加到 mock 数据里一起用
不足继续使用我们的 mock 数据。报告里有一句可以直接用来说服客户的原因（例如“缺少客户等级和反馈类型，Agent 无法判断重要和紧急，评估结果没有可比性”）

也可以整件事交给 coding agent：提示词 data/prompts/01-assess-customer-data.md（先把里面的 <客户文件路径> 换成实际路径）。提示词使用说明：data/prompts/README.md。

本仓库会公开发布：客户的真实数据只能放在 data/customer/，不要复制到其它目录，也不要提交。
2.4

按讨论反馈修改 mock 数据

10 分钟

把现场确认的参数填进模板，再让 coding agent 按模板重新生成 mock 数据。

  1. 打开参数模板 data/templates/mock-data-params.yaml，按讨论结论修改（月份、条数、需求类别配比、客户行业、来源渠道）。不改任何参数 = 原样复现仓库里的 60 条数据。
  2. 如果需要“种子库里没有”的新类型需求，让 coding agent 按提示词 data/prompts/02-regenerate-mock-data.md 把新条目写进 data/templates/extra-feedback.jsonl（格式见 extra-feedback.example.jsonl）：
claude "$(cat data/prompts/02-regenerate-mock-data.md)"

（或者先运行 claude，再把提示词文件内容粘贴进去。）只改参数、不加新条目时，直接运行生成脚本：

python3 data/tools/generate_mock_data.py

脚本：data/tools/generate_mock_data.py（同样的参数 + 同样的随机种子 = 同样的结果）

预期结果：data/feedback_last_month.jsonl 与 .csv 按新参数重新生成，脚本打印条数和各类别数量。
默认不覆盖黄金集。黄金集请走 2.5 的流程修改，这样每条改动都有记录。
2.5

按讨论反馈修改黄金集

15 分钟

把现场确认的标注口径填进模板，再让 coding agent 按模板更新黄金集。

  1. 口径类结论（标签用“是/否”还是 P0/P1/P2、不可自动拒绝的规则、能力目录补充）写进 data/templates/discussion-feedback.md。
  2. 逐条意见写进 data/templates/golden-set-feedback.csv：“操作”列填 保留 / 修改 / 删除 / 新增，改标签就直接改对应列。可以先用当前黄金集预填这张表：
python3 data/tools/golden_tool.py feedback-template
  1. 把两份模板交给 coding agent，它会读模板、调用脚本更新黄金集并校验：
claude "$(cat data/prompts/03-update-golden-set.md)"

提示词：03-update-golden-set.md（最常用）。相关的还有：补充 / 纠正能力目录 04-update-capability-catalog.md（读模板第 3 节）；从“是/否”切换到 P0/P1/P2 05-switch-label-scheme.md（读模板第 1.1 节）。

如果只是按 CSV 改标签（不需要 coding agent 写新样例），也可以直接运行：

python3 data/tools/golden_tool.py apply-feedback --feedback data/templates/golden-set-feedback.csv --version v2

选了分级（P0/P1/P2）但还有条目没填优先级时，可以先按“重要 / 紧急”自动推导一版再人工确认：python3 data/tools/golden_tool.py fill-levels

预期结果：data/golden/golden_set.jsonl 更新，脚本打印改了几条、新增几条，并给出新的标签分布。
标注标准变了，记得同时更新 LABELING_GUIDE.md（coding agent 提示词会提醒你）。后面第 8 章优化 Agent 时，提示词也要和新口径一致。
2.6

校验黄金集并冻结版本

3 分钟

用脚本检查黄金集格式和标签分布，确认后冻结一个版本，后面评估都以它为准。

python3 data/tools/golden_tool.py validate
python3 data/tools/golden_tool.py freeze

脚本：data/tools/golden_tool.py。freeze = 校验 + 导出 CSV / AgentCore 数据集格式 + 写 MANIFEST.json + 把黄金集同步进评估器目录（evaluators/*/golden_set.json）。

预期输出（validate）： 
黄金集共 30 条
- 是否重要：否 17，是 13
- 是否紧急：否 24，是 6
- 处理建议：待评估 6，拒绝 13，迭代 11（多答案可接受 6 条）
...
校验通过
黄金集冻结后再修改，需要重新运行 freeze 并重新注册评估器（第 6 章 ./30-create-evaluators.sh），否则评估器里还是旧答案。
