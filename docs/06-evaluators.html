6注册评估器 + 开启在线评估 A/B 通用

评估器是“打分规则”。我们事先写好并测试过自定义评估器，再加上内置评估器，一起注册到 AgentCore Evaluations；最后开启在线评估，让分数自动显示在 CloudWatch 控制台。

在线评估只给开启之后产生的新 session 打分。所以一定要先完成本章（尤其 6.6），再到第 7 章跑黄金集。
6.1

认识评估器

5 分钟

标签准确率直接对应“三项指标 70%”目标；话术质量用 LLM 评审。

注册名（前缀 s12lab_zhang3_）类型 · 级别打什么分代码
label_accuracy代码型（Lambda）· TRACE三项标签（是否重要 / 是否紧急 / 处理建议）与黄金集一致的比例 0–1；Pass = 三项全对；误拒了“不可自动拒绝”的需求记 CriticalFailevaluators/s12_label_accuracy/
label_important代码型 · TRACE只看“是否重要”，对 = 1、错 = 0；控制台里的平均分 = 该项准确率
label_urgent代码型 · TRACE只看“是否紧急”
label_decision代码型 · TRACE只看“处理建议”（模糊样例允许多个可接受答案）
reject_quality代码型（Lambda 内调用评审模型）· TRACE拒绝理由与客户话术质量 0–1（理由专业性 / 理解与礼貌 / 原因说明 / 替代方案 / 风险控制），≥ 0.7 为 Pass；不是拒绝的需求返回 Skippedevaluators/s12_reject_quality/
reject_quality_llm原生 LLM-as-a-judge · TRACE同一套评审标准，用 AgentCore 自带的 LLM 评审实现（5 档；非拒绝给“不适用”档）llm_judge_config/
Builtin.Correctness内置 · TRACE对照黄金集的期望答案判断回答是否正确AgentCore 内置
Builtin.Helpfulness内置 · TRACE回答对用户是否有帮助

评估器说明：evaluators/README.md · 评审标准：rubric.py · 标注口径：LABELING_GUIDE.md

黄金集答案随 Lambda 一起打包（evaluators/*/golden_set.json），所以在线评估（没有“标准答案”输入）也能按需求编号找到答案打分。黄金集改了要重新 freeze 并重新运行 6.3。

6.5

开启在线评估（分数显示到控制台）

3 分钟

让 Evaluations 自动给新 session 打分并写入 CloudWatch，控制台的 Evaluations 页签才有数据。

A 版（本机 / 自有 Agent）
./33-online-eval.sh enable --path a
数据源：aws/spans + 日志组 /aws/bedrock-agentcore/s12lab-zhang3-local-agent，服务名 s12lab-zhang3-local-agent。
B 版（AgentCore Runtime）
./33-online-eval.sh enable --path b
数据源：aws/spans + Runtime 日志组，服务名 s12lab_zhang3_agent.DEFAULT。

脚本：33-online-eval.sh → labkit/online.py（采样 100%，session 空闲 2 分钟后开始打分；挂载 label_accuracy / label_important / label_urgent / label_decision / reject_quality + Builtin.Helpfulness）

预期输出： 
✅ 已创建在线评估配置 s12lab_zhang3_online_b（s12lab_zhang3_online_b-XyZ...），采样 100%，session 空闲 2 分钟后打分
   之后每个新 session 都会自动评分，结果写入 CloudWatch：
   CloudWatch 控制台 → GenAI Observability → Bedrock AgentCore → 你的 Agent → Evaluations
查看状态：./33-online-eval.sh status。在线评估和第 7 章的“按需评估”用的是同一组评估器：按需评估马上出结果（用于对比页），在线评估把分数留在控制台（用于展示和持续监控）。
