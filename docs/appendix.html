X.1

配置项说明

所有区域、模型、资源名都在一个配置文件里。

共享配置：config/lab.env；个人覆盖：config/local.env（不提交，由 tools/set-suffix.sh、tools/use-model.sh、40-switch-version.sh 写入）。读取顺序：lab.env → local.env → 当前 shell 的环境变量（后者优先）。查看最终生效的值：./00-config.sh。

配置项默认值含义
AWS_REGIONus-west-2实验区域（us-west-2 或 us-east-1）
LAB_PREFIXs12lab所有实验资源名的前缀，清理脚本按它查找
LAB_SUFFIX（无，必填）个人后缀，写在 config/local.env：./tools/set-suffix.sh zhang3
AGENT_MODEL_IDus.anthropic.claude-sonnet-5-5Agent 本体模型（Bedrock 推理配置文件 ID）
JUDGE_MODEL_IDus.anthropic.claude-sonnet-5-5LLM 评审评估器使用的模型
FALLBACK_MODEL_IDus.amazon.nova-2-lite-v1:0一行切换的备选模型（Amazon Nova 2 Lite）
CODING_AGENT_MODEL_ID / CODING_AGENT_FAST_MODEL_IDSonnet 5.5 / Haiku 5.5EC2 上 Claude Code 使用的模型（安装脚本读取）
AGENT_VERSIONv0Agent 版本（v0 基线 / v1 优化版 / 你自己写的 v2）
TARGET_ACCURACY0.70三项标签准确率目标
RUNTIME_PYTHONPYTHON_3_12AgentCore Runtime 直接代码部署使用的 Python 版本
AWS_PROFILE（空）仅在笔记本上运行时使用的 AWS CLI profile；EC2 上留空（用实例角色）

资源名如何从前缀和后缀推导出来：labkit/config.py 的 derive()。

X.2

切换区域（us-west-2 / us-east-1）

改一行配置即可切换。

  • EC2 上：区域自动跟随 EC2 所在区域（setup-ec2.sh 读取实例元数据写入 AWS_REGION，优先于 lab.env），一般不用改；./01-check-env.sh 发现两者不一致会提示。
  • 笔记本上：在 config/local.env 里加一行 AWS_REGION=us-east-1，或者直接修改 config/lab.env。

us-west-2 已完整跑通全部步骤；us-east-1 已确认模型可调用（us.anthropic.claude-sonnet-5-5、us.amazon.nova-2-lite-v1:0）、AgentCore 控制面可用（内置评估器、Runtime 列表），但没有在 us-east-1 端到端部署过（见 X.6）。切换区域后，第 1.8 步（Transaction Search）要在新区域再做一次，资源也要在新区域重新创建。

切换前先清理旧区域：在旧区域运行 ./99-cleanup.sh，再改区域。清理脚本只处理“当前区域”的资源（IAM 角色名和 S3 桶名都带区域后缀，如 s12lab-zhang3-runtime-role-us-west-2），所以不会误删另一个区域的资源，但也不会替你清理另一个区域。

用 us-east-1 做一次快速检查（只读 + 一次模型调用，不创建资源）：

AWS_REGION=us-east-1 ./01-check-env.sh
② 配置与身份
  ✅ 区域 us-east-1 · 个人后缀 zhang3 · 资源名前缀 s12lab-zhang3
  …
③ Bedrock 模型
  ✅ Agent 模型 us.anthropic.claude-sonnet-5-5 可用（回复：收到）
④ CloudWatch Transaction Search
  ⚠️  未开启（当前 XRay/ACTIVE）→ 运行 ./02-enable-observability.sh

切换模型（Claude Sonnet 5.5 → Amazon Nova）

Claude 不可用时，一行命令换成 Nova。

./tools/use-model.sh nova      # Agent 和评审模型都切到 FALLBACK_MODEL_ID
./tools/use-model.sh claude    # 切回 config/lab.env 的默认模型
./tools/use-model.sh us.anthropic.claude-haiku-5-5   # 指定任意模型 ID
预期输出：

AGENT_MODEL_ID=us.amazon.nova-2-lite-v1:0

   B 版需重新部署 Runtime 才生效：./20-B-deploy-runtime.sh；评审模型需重跑 ./30-create-evaluators.sh

实测：切到 Nova 后 ./01-check-env.sh 显示 ✅ Agent 模型 us.amazon.nova-2-lite-v1:0 可用（回复：收到），Agent（含工具调用）正常工作且更快：

  [ 1/1] FB-2610-001        4.6s  重要=是 紧急=否 建议=迭代

脚本：tools/use-model.sh。切换后先跑 ./01-check-env.sh 确认模型可用。换模型也是一种“优化”：用同一份黄金集评估，就能比较不同模型的准确率、耗时和成本。

常见问题排查

按报错关键词查找解决办法。

现象 / 报错关键词原因怎么办
AccessDeniedException（调用模型时）账号没有开通该模型，或模型 ID 在当前区域不可用./tools/use-model.sh nova 后重跑 ./01-check-env.sh；或请讲师在 Bedrock 控制台开通模型
LAB_SUFFIX 未设置或格式不对没设置个人后缀./tools/set-suffix.sh zhang3
no spans found in CloudWatch for this sessiontrace 还没写进 CloudWatch（1–3 分钟延迟），或 Transaction Search 没开等 2–3 分钟重跑 ./31-run-eval.sh；./01-check-env.sh 第 ④ 项不是“已开启”就运行 ./02-enable-observability.sh
Runtime CREATE_FAILED / UPDATE_FAILED常见是依赖包不是 linux/arm64 版本rm -rf build/runtime 后重跑 ./20-B-deploy-runtime.sh；看 Runtime 日志组 /aws/bedrock-agentcore/runtimes/<ID>-DEFAULT
调用 Runtime 超时 / 第一次很慢冷启动再调用一次
已被在线评估锁定，删除后重建 / Cannot update locked evaluator评估器挂到在线评估配置后会被永久锁定（停用或删除配置都不会解锁，但可以删除）不用手动处理：./30-create-evaluators.sh 会临时删除你的在线评估配置、删除并重建有变化的评估器、再重建在线评估配置。只更新黄金集时只改 Lambda 代码，不涉及锁定
批量调用时个别条目 RuntimeClientErrorRuntime 偶发的瞬时错误脚本已自动对同一条重试 2 次；仍失败的条目评估时跳过，失败多就重跑 ./21-B-run-golden.sh
tee: /dev/stderr: Permission denied（旧版脚本）旧版 32-compare.sh / 34-triage-report.sh 在没有终端的环境里会报这个错已修复；git pull 拿最新脚本即可
OpenTelemetry 打印 WARNING … Skipping installation of LoggingHandler / Attempting to instrument while already instrumentedOpenTelemetry 自己的提示正常现象，忽略即可
Transaction Search 一直 PENDING新账号首次开启需要 5–10 分钟继续做第 2 章，稍后重跑 ./02-enable-observability.sh（已开启会直接提示）
uv / pip 卡住不动或非常慢网络慢，或另一个 uv 进程占用了缓存锁等一等；确认没有其它安装在跑（ps aux | grep uv）；必要时 export UV_CACHE_DIR=/tmp/uvcache 后重跑
Session Manager 连不上 / 实例“未上线”实例刚启动，或实例角色没有 SSM 权限再等 2–3 分钟；手动创建的 EC2 检查 IAM 实例配置文件（1.3）
控制台看不到自己的资源区域不对右上角切到实验区域
Evaluations 页签没有分数在线评估在 session 空闲 2 分钟后才打分；或在线评估是在跑黄金集之后才开启的等 5–10 分钟；确认 ./33-online-eval.sh status 为启用，再跑一次黄金集
重新登录后命令找不到 / Python 报缺包没有切到 ec2-user 或没进虚拟环境sudo su - ec2-user → cd ~/scenario12-lab && source .venv/bin/activate
