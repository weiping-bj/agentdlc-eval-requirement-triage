B3部署 V0 到 AgentCore Runtime B 版

把我们准备好的 mock agent（V0，故意留有缺陷）部署到 AgentCore Runtime，Runtime 会自动把 trace 发到 CloudWatch。

前提：已完成第 1 章（尤其 1.8 Transaction Search）和第 2 章。命令都在 EC2 的 ~/scenario12-lab 下执行。
B3.1

认识 mock agent（V0）

3 分钟

了解 Agent 的输入、输出和工具，知道 V0 故意留了哪些缺陷。

文件作用
agent/main.pyAgentCore Runtime 入口：收到 {"feedback": {...}}，返回判断结果 JSON
agent/s12agent/core.py构建 Strands Agent（模型、提示词、工具），解析输出
prompts/v0.md · prompts/v1.mdV0 / V1 的系统提示词（V1 是第 8 章的参考优化版）
agent/s12agent/tools.py工具：V0 只有 lookup_capability；V1 有 search_capabilities + find_similar_requests

V0 故意留下的缺陷（第 7 章的评估会把它们暴露出来）：

  • 判断口径含糊：只说“判断是否重要 / 紧急”，没有标准；
  • 容易被客户的措辞带偏：客户写“很急”就可能判紧急；
  • 工具只返回能力名称，看不到“已支持 / 部分支持 / 明确不做”，分不清“已有能力”和“真实缺口”；
  • 没有“相似需求统计”，判断不了是不是通用需求；
  • 没有“不可自动拒绝”的规则（数据丢失、安全、合规、合同承诺），也没要求话术给替代方案。

B3.3

打包、上传并创建 AgentCore Runtime（一条命令）

5 分钟

Runtime 支持直接部署代码包，不需要 Docker；脚本一次完成打包、上传、建角色、建 Runtime 并等待就绪。

./20-B-deploy-runtime.sh

脚本：20-B-deploy-runtime.sh → labkit/runtime.py

脚本依次做了这些事：

  1. 用 uv 下载 linux/arm64 版依赖（Runtime 运行在 ARM 上），和 agent/ 代码、能力目录一起打成 zip；
  2. 上传到你的私有桶 s3://s12lab-zhang3-<账号>-<区域>/runtime/；
  3. 创建执行角色 s12lab-zhang3-runtime-role（调用 Bedrock 模型、写 CloudWatch）；
  4. 创建 Runtime s12lab_zhang3_agent，入口 opentelemetry-instrument main.py（自动埋点），等待状态变为 READY（约 2–4 分钟）。
