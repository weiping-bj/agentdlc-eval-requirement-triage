在控制台确认 Runtime 已就绪，并找到 B3.4 那次调用产生的 trace。完整黄金集在第 7 章跑（要先注册评估器、开启在线评估）。

B4.1

在 Bedrock AgentCore 控制台查看 Runtime

2 分钟

确认 Runtime、版本和环境变量（Agent 版本、模型）都符合预期。

  1. 控制台顶部搜索 Bedrock AgentCore → 打开 Amazon Bedrock AgentCore 控制台（区域与实验一致）。
  2. 左侧 Runtime（Agent runtime）→ 列表里找到 s12lab_zhang3_agent，状态 Ready。
  3. 点进去：能看到版本号、DEFAULT 端点、执行角色 s12lab-zhang3-runtime-role，以及环境变量 AGENT_VERSION=v0、AGENT_MODEL_ID。
预期结果：Runtime 状态 Ready，版本 1（第 8 章重新部署 V1 后变为版本 2）。命令行查看同样的信息：./20-B-deploy-runtime.sh status。控制台菜单名称可能随版本略有不同。
B4.2

在 CloudWatch GenAI Observability 查看 trace

3 分钟

在控制台看到 Agent、会话、trace 和工具调用；后面的评估就是读这些数据。

  1. B3.4 之后等 2–3 分钟。打开 CloudWatch → 左侧 GenAI Observability → Bedrock AgentCore。
  2. Agents 列表找到 s12lab_zhang3_agent → 点进去，Overview 里有会话数、调用次数、延迟、token 用量。
  3. 切到 Sessions → 点那个 s12lab-zhang3-smoke-… 会话 → Traces：调用树里有 s12lab.triage → invoke_agent → chat 和 execute_tool lookup_capability，点开 span 能看到模型的输入和输出。
预期结果：能看到 1 个会话、1 个 trace，以及模型和工具调用的耗时。Runtime 上的服务名是 s12lab_zhang3_agent.DEFAULT（在线评估和指标都按这个名字聚合）。
Runtime 自己的日志在 CloudWatch Logs 日志组 /aws/bedrock-agentcore/runtimes/<Runtime ID>-DEFAULT，调用报错时先看这里。
