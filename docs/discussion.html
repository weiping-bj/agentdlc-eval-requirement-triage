D.2

五维讨论提纲

讨论 15 分钟

每一维对应黄金集里的一类“考点”。每维挑 1–2 个问题讨论即可，不求全。

维度讨论问题（场景 12）落到黄金集 / 评估上的样子
认知Agent 要“懂平台”：哪些能力已经有（只是客户不会用）？哪些明确不做（超出平台定位）？什么叫“通用需求”——几个客户提过才算？黄金集里放“已有能力被重复提出”“超出定位”“单客户定制”三类样例；能力目录是 Agent 的知识来源
质量三项判断谁说了算——产品还是研发？两边意见不一致时以谁为准？拒绝理由要专业到什么程度、话术要不要能直接发给客户？标签准确率评估器（对应 70% 目标）；拒绝话术 LLM 评审评估器（专业性 / 说服力 / 是否给替代方案）
责任哪些需求不能让 AI 自动拒绝（安全合规、数据丢失、战略大客户、合同承诺）？自动拒绝后谁复核、客户不服怎么办？“不可自动拒绝”样例必须判为“待评估”或“迭代”；评估中误拒比漏拒更严重
成本研发难度怎么估（人天？复杂度档位？）每条需求愿意花多少钱/时间做判断？误拒一条好需求的代价有多大？样例里带“预估难度”；评估报告给出每条 token 与耗时
性能是每月批量跑一次，还是需求一进来就实时判断？上个月大概多少条需求？多久要出结果？批量脚本 + 延迟统计；在线评估（第 6.5 步）对应“实时”模式
D.3

必须当场决定：标签用“是/否”还是“P0/P1/P2”

讨论 3 分钟

这决定黄金集怎么标、评估器怎么算准确率。我们默认用“是/否”，输出结构里已预留分级字段，现场选哪种都能当天跑通。

方案好处代价下午要改什么
A. 二元（默认）
是否重要 是/否 · 是否紧急 是/否 · 处理建议 迭代/拒绝/待评估		和“三项指标 70%”目标一一对应；标注快，产品研发容易对齐粒度粗，“重要”内部无法排序不用改
B. 分级
优先级 P0/P1/P2 + 处理建议		直接可用于排期；分布图更有信息量标注分歧更大；70% 目标需要重新定义（例如“等级完全一致”或“相差不超过一级”）黄金集填 level 字段（可先 golden_tool.py fill-levels 自动推导）；让 coding agent 执行 05-switch-label-scheme.md 切换口径
记录方式：在 讨论反馈模板 第 1 节勾选 A 或 B，并写下每一档的判断标准（一句话即可）。

10 分钟分享怎么讲

分享 3 分钟/组

  1. 我们的标签口径是：……（是/否 或 P0/P1/P2）
