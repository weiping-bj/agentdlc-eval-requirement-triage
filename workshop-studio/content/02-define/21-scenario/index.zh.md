**用时**：约 5 分钟

## 读角色卡 {#s-2-1-role}

下一步画鱼骨图时，你们小组扮演**业务方**。先把角色卡读一遍：

```bash
cat data/scenario/role-card.md
```

:::alert{header="场景包：企业软件平台的需求评审" type="info"}
角色卡写了业务方是谁、要什么、现在怎么评审、过去踩过哪些坑，以及回答时的注意事项。访谈时用卡里的事实和你们自己的经验回答；卡里没写、自己也说不准的，就说“不知道”或“没有”，不要现编数字。换场景时，整份角色卡和 `data/` 下的数据一起替换。
:::

## 小组分工 {#s-2-1-roles}

::::alert{header="鱼骨图访谈怎么进行（一页流程）" type="info"}
**分工**
- **操作员**（1 人）：在自己的 EC2 上运行 Claude Code，把小组商量好的回答打进去；
- **计时员**（1 人）：盯时间，到点提醒（见下面的时间点）；
- **业务方**（其余的人）：按角色卡加上自己的经验回答问题。

**节奏**（建议 25 分钟，以现场讲师安排为准）
1. 主持人（Claude Code）一次只问一个问题；
2. 小组**先简短商量**，再由操作员打字回答；
3. 主持人把回答改写成便签读回：准确就说“对”，不准确就指出哪里不对；
4. 大约 20 分钟时讲师提醒；25 分钟左右讲师喊时间到，操作员输入“时间到，后面不答了”，主持人收尾出图。
::::

## 认识输入数据和黄金集 {#s-2-1-data}

| 文件 | 内容 |
|---|---|
| `data/feedback_last_month.jsonl` | 60 条“上个月的需求反馈”，每行一条：编号、标题、描述、客户、行业、客户等级、渠道、模块、提交日期、反馈类型、是否合同承诺。不含任何标签，这是 Agent 的输入 |
| `data/capability_catalog.json` | 平台能力目录（39 项：已支持 24 · 部分支持 8 · 明确不做 7），每项有限制、替代方案和菜单路径。Agent 判断“已有能力 / 真实缺口 / 超出定位”的依据 |
| `data/golden/golden_set.jsonl` | 黄金集：30 条带标准答案的样例（期望标签、可接受的其它建议、是否可自动拒绝、拒绝要点、话术要点、标注理由、五维标签、样例类型） |
| `data/golden/LABELING_GUIDE.md` | 标注标准：什么算重要、紧急，何时迭代 / 拒绝 / 待评估，哪些不可自动拒绝 |

看一眼黄金集现在的分布：

```bash
python3 data/tools/golden_tool.py stats
```

**预期输出**：

```
黄金集共 30 条
- 是否重要：否 17，是 13
- 是否紧急：否 24，是 6
- 处理建议：待评估 6，拒绝 13，迭代 11（多答案可接受 6 条）
- 优先级：P0 6，P1 7，P2 17
- 样例类型：对抗 4，应拒绝 7，模糊 9，简单 10
- 五维覆盖：性能 5，成本 6，认知 12，责任 12，质量 10
- 不可自动拒绝：6 条
```

这是实验自带的黄金集。到 2.4 结束时，它会变成你们补过样本、**冻结**过的那一版。

V0（第 3 章部署、第 4 章评估）是故意偏弱的基线：口径是“战略 / KA 客户提的就算重要、客户说着急就算紧急、尽量不拒绝”，唯一的工具只返回能力名称，没有“不可自动拒绝”的规则。想看它的提示词：`cat agent/adlc_agent/prompts/v0.md`。先不用改它，等第 4 章的评估告诉你它错在哪。

::::expand{header="（可选）在笔记本浏览器里看这三份数据"}

```bash
./tools/publish-data-pages.sh
```

桶始终禁止公开访问。以后数据改了，重跑同一条命令，链接不变。
