> **你在这里**：**① 定义** → ② 构建 → ③ 评估 → ④ 发布 → ⑤ 观测 → ⑥ 回流 · 圆心：黄金标准

**用时**：约 4 分钟

鱼骨图回答“什么会挡住上线”；判据把每条障碍翻译成**一条可以打分的要求**：主语是 Agent，谓语能在 Agent 的输出或 trace 上观察到。例如障碍“数据丢失类缺陷被当体验问题自动拒掉”对应判据“Agent 不把数据丢失、安全、合规、合同承诺、线上缺陷类反馈判为拒绝”。

## 让 Claude Code 写判据表 {#s-2-3-run}

在 Claude Code 里输入（把路径换成 2.2 里 Claude Code 打印的那个）：

```
用 adlc-criteria 把 /home/ec2-user/adlc-lab/outputs/fishbone/第3组-2026-11-14 的鱼骨图翻译成判据表
```

它会依次做（大部分不需要你回答）：

1. 读这个目录里的 `fishbone-data.json`，用 `.claude/skills/adlc-criteria/scripts/criteria.py skeleton` 建草稿；
2. 给每条已确认的障碍写一条判据，定**维度**、**档位**、**执行方式**，挑出实验里**确实检查这个谓语**的现有检查；
3. 运行 `criteria.py build` 校验并算出覆盖情况，写出 `criteria.json`（以它为准）和 `criteria.md`；
4. 把判据表压缩成一张表读给你们，请业务方签字。

| 档位 | 含义 | 例子 |
|---|---|---|
| **红线** | 违反一次就是事故，0 违例，一票否决 | 误拒不可自动拒绝的需求；话术里出现其他客户名称 |
| **门禁** | 达到阈值才放行 | 处理建议准确率 ≥ 0.70（角色卡里领导定的目标） |
| **观测** | 只看趋势，不进发布结论 | 待评估占比、每条耗时 |

| 执行方式 | 用在哪里 |
|---|---|
| 代码断言 | 和黄金集逐字段比对、规则匹配；能用代码判的就不交给模型 |
| 裁判（LLM-as-a-Judge） | 主观但有评分标准的部分，例如拒绝话术的专业性 |
| 内置评估器 | `Builtin.Correctness`、`Builtin.Helpfulness` |
| 指标读数 | 成本和性能：从运行记录读耗时、token 用量、失败条数 |

**覆盖**由脚本对照 `.claude/skills/adlc-criteria/evaluator-coverage.json` 算出，不靠感觉：**已覆盖**（现有评估器就在查，黄金集里也有能检验它的样本）、**部分覆盖**（只查到一部分，或者评估器能判、但黄金集里还没有这类样本）、**未覆盖**（现有评估器和读数都不查它，要新写评估器）。

## 签字与预览 {#s-2-3-sign}

听完读回，要改哪条的档位或阈值就直接说；没有异议就签字（说“签字”或“可以”）。然后重跑 2.2 的发布命令（同一条命令、同一个路径；Claude Code 也可能替你运行它），预览链接里会多出“判据表预览”。

**预期输出**（`criteria.py build` 的结尾，条数和判据是你们自己的）：

```
✅ 判据表 14 条 → outputs/fishbone/第3组-2026-11-14/criteria.json、outputs/fishbone/第3组-2026-11-14/criteria.md
   三档：{"门禁": 9, "红线": 4, "观测": 1}  覆盖：{"已覆盖": 5, "部分覆盖": 8, "未覆盖": 1}
   可以靠补黄金样本补上缺口的判据：C-07
   ⚠️ “紧急=否”占比超过 80%：全判“否”也能拿高分，请同时看“紧急=是”的召回率
   黄金样本提议 1 条（预览，未写入 data/）→ outputs/fishbone/第3组-2026-11-14/golden-proposals.csv
```

“未覆盖”的判据就是将来要新写的评估器或断言（例如菜单路径对照能力目录的代码断言）；这次实验不写新评估器，把它们留在判据表里。
