> **你在这里**：**① 定义** → ② 构建 → ③ 评估 → ④ 发布 → ⑤ 观测 → ⑥ 回流 · 圆心：黄金标准

:image[你在这里：① 定义]{src="/static/images/flywheel-define.svg" width=220 height=220}

**用时**：约 47 分钟

定义环**产出圆心**：在动手写任何代码之前，先和业务方一起把“什么是好”说清楚，并写成可以打分的东西。这一章走完一遍定义环的最小闭环：

| 步骤 | 做什么 | 产出 | 用时 |
|---|---|---|---|
| [2.1 读角色卡、分工](/02-define/21-scenario) | 读角色卡，分好操作员 / 计时员 / 业务方，认识输入数据和黄金集 | 对场景的共同理解 | 5 分钟 |
| [2.2 画鱼骨图](/02-define/22-fishbone) | Claude Code 主持访谈（`adlc-fishbone` skill，角色卡作背景材料），你们扮演业务方 | 业务方确认过的上线障碍 | 25 分钟（建议） |
| [2.3 障碍 → 判据表](/02-define/23-criteria) | `adlc-criteria` skill 把障碍翻译成判据：档位、执行方式、现有评估器是否覆盖 | 业务方签字的判据表 | 7 分钟 |
| [2.4 判据 → 黄金集](/02-define/24-golden) | 给没被覆盖的判据补 1–3 条黄金样本，冻结黄金集 | 冻结的黄金集（圆心） | 5 分钟 |
| [2.5 讨论：如果要 P0/P1/P2 分级](/02-define/25-discussion) | 改一个标准，影响链上哪些东西要跟着变 | 影响链 | 5 分钟 |

所有命令都在实验 EC2 的 `~/adlc-lab` 里运行（先 `sudo su - ec2-user`）。2.2–2.4 是小组一起在**操作员**的 EC2 上做；第 3 章起每人回到自己的 EC2，见 2.4 末尾的说明。

**落后了怎么办**：跳过 2.1 的可选数据网页；2.3 签字后先不发布预览（2.4 结束时发布一次）；2.4 只接受第一条提议。
