> **你在这里**：**① 定义** → ② 构建 → ③ 评估 → ④ 发布 → ⑤ 观测 → ⑥ 回流 · 圆心：黄金标准

**用时**：约 30 分钟（鱼骨图约 25 分钟，判据表约 5 分钟）

主线用的是实验场景（需求评审）。这个扩展用**你们自己组的 Agent 场景**再走一遍定义环：同一个 `adlc-fishbone` / `adlc-criteria` skill，没有角色卡，大家按自己的真实经验回答。

:::alert{header="不要输入保密信息" type="warning"}
访谈内容会发给实验账号里的 Bedrock 模型，输出文件留在实验 EC2 上，预览页在你的私有 S3 桶里。不要写客户名、人名、账号、内部系统地址或任何保密数字；需要时用“某客户”“约 X 条”这类说法。
:::

## E4.1 开始访谈 {#e4-1}

分工和节奏同第 2.1 步（操作员 / 计时员 / 业务方，约 20 分钟提醒、约 25 分钟收尾）。在 `~/adlc-lab` 里运行 `claude`，输入：

```
用 adlc-fishbone 画鱼骨图，用我们自己的场景，我们是第 3 组
```

没有背景材料时，主持人会多问几个场景问题（这个 Agent 给谁用、最重要的一件事是什么、哪种错误一旦发生会立刻叫停上线）。之后的问法、便签确认和“时间到，后面不答了”的收尾都和第 2.2 步一样。

收尾时 Claude Code 会打印输出目录的完整路径。发布预览（把路径换成它打印的那个）：

```bash
./tools/publish-define-pages.sh /home/ec2-user/adlc-lab/outputs/fishbone/<目录>
```

## E4.2 判据表 {#e4-2}

```
用 adlc-criteria 把 /home/ec2-user/adlc-lab/outputs/fishbone/<目录> 的鱼骨图翻译成判据表
```

自己场景的判据大多会是“未覆盖”：实验自带的评估器是为需求分诊 Agent 写的。这份“未覆盖”清单，就是你们自己的 Agent 要新写的评估器和断言的清单。**不要**补黄金样本到实验的黄金集里（它是需求分诊 Agent 的数据契约），skill 也会跳过这一步。签字后重跑上面的发布命令，预览里会多出判据表。

## E4.3 带走什么 {#e4-3}

- `fishbone-data.json`、`fishbone.drawio`、`qa-record.md`：会后可以和真正的业务方再过一遍，把“不知道”的地方补上；
- `criteria.json` / `criteria.md`：每条判据的档位、阈值、执行方式和“未覆盖”的缺口；
- 接入评估的方法：扩展[自带 Agent 接入指南](/90-extensions/e3-own-agent)。

实验 EC2 在活动结束后会被回收：需要的文件在活动结束前从 S3 控制台下载（预览页所在的桶里也有 `fishbone.drawio`）。

## 检查一下 {#e4-check}

**你们的判据表里，每条红线都有能检验它的样本吗？** 如果还没有黄金集，第一批黄金样本就从这些红线开始写：圆心还没产出之前，后面的构建、评估都没有参照物。
